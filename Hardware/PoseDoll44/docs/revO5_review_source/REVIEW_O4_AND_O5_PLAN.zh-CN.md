# PoseDoll Rev O4 独立审查与 O5 实施指导

## 结论

保留已经建立的静态采集软件架构。下一轮以 **A（14 芯）所用采集拓扑的真实传感器—区域节点—G0—主机桥接—UE 闭环** 为主线；C（四芯）并行完成一组有边界的电气样件和同条件九轴单臂比较。不要预设 C 必须替代 A，也不要等待整个人偶制造完成才验证真实采集。

A 也是未完成的硬件设计，不是已有合格实物。先用经审查的台架实现或开发板组合证明传感与事务链，不必为此提前生产全套 A 成品板。台架通过不等于最终紧凑板通过。

必须在制线或板件放行前纠正一项选型：当前 JST SH 的 SSH-003T-P0.2-H 压接端子适用 AWG 32–28；此前沿用的 26 AWG 建议不在厂家范围内。不得仅因绝缘外径看似能装入，就当成合格压接。

软件方面应补齐两个恢复路径：PDR4 执行成功但回复丢失后的幂等重试，以及取消旧采集后立即开启新采集时的迟到消息隔离。它们都不是已发生的实物事故；当前代码前者只有原型，后者会安全拒绝而不是写入旧姿势。

## 4. O5-01：修正线径、端子和供电的联动设计

当前 `scripts/build_revo4_electronics.py` 给 J50 指定四针 SH 系列和 `SSH-003T-P0.2-H`。[E1] JST 官方 eSH 目录第 2 页列该端子导体为 AWG #32–#28（0.032–0.081 mm²）、绝缘外径 0.4–0.8 mm。[M1] 26 AWG 不在此范围。先前沿用 26 AWG 的建议在端子适配上不充分，本轮纠正，不把它归咎于 Codex。

建议第一候选为：继续使用 SH4，改用厂家范围内的真实 28 AWG 柔性导线，电源与数据选定确切结构，按实际单向最长路径而非仅板间直线距离核算。必须包括接头、压接、线端应力释放、允许弯曲路径及装配余量。不能把 0.8 mm 外径假设代替供应商料号。

重算：

`Vremote_min = Vsource_min − Ipeak × (R正线 + R地线 + R接点 + R开关 + R板路)`

与所有远端器件的工作范围比较；THVD1400 的供电工作下限为 3.0 V，不能用 MCU 仍能运行来证明整板可采集。[M2] AS5048 的所用供电方式、板级引脚接法和有效测角范围也须一起审核。电压裕量由误差/温度/电流预算推导，不只压在线上。

O4 36 组模型中四组低于 3.0 V、最低约 2.951 V，以及 250 mA 可能触发限流，都是有条件敏感性，不是测得的最大电流/故障。TPS2553 的 100 kΩ 名义设置不能当成精确 250 mA 门槛。[H2,M3]

当有效 28 AWG、实际最长线及最坏峰值下无法闭合电压和热预算时，平行比较：

- 独立的 5 V 干线 + 远端 3.3 V 稳压版本，重新计算新增稳压器、保护、去耦、失效状态和占用体；不能直接向当前 J50 的 3.3 V 引脚送 5 V。
- 真正适用 26 AWG 的四针连接器，连同配合头/固定脚/线尾/工具重新排布；厂商确认具体型号后才冻结。

不把短 28 AWG 尾线拼接 26 AWG 主干作为默认捷径。采用时须明示额外接点、应力释放、柔性和维修代价。禁止削掉导线股数来装不适用的端子。

验收：线束型号表与端子范围一致；压接方按厂家工具和工艺交付，带目检/拉脱/接触电阻结果；示波器测源端和远端的正常、启动、重试、短路恢复瞬态；记录限流与故障信号。满载/无线最坏供电工况必须纳入，不静默取消无线来降低功耗。

## 5. O5-02：让重试和防重放同时成立

`pdr4_accept_request()` 在首次接受时立即推进 `last_scan`，相同编号再次到达会拒绝。[R1,R2] 原主机测试就是这样定义的：防重复成立，但目前没有驱动层幂等处理。

本次实际原 C 执行输出为：

```json
{"first_request_accepted":1,"retry_after_lost_response":0,"second_retry":0,"last_scan":1}
```

这说明不能把“再发同一请求两次”直接代入 92.219 ms 的时序预算并声称恢复成功。既有时间预算也已经注明不含 CAN/G0/USB/OS。[H2]

首选在运行时补有限状态：IDLE、ACQUIRING、REPLY_READY、FAULT；缓存键至少含 link_nonce/generation、capture_counter、capture_id、scan_id，并绑定当前真实卫星启动身份。接收相同键同内容时：

- 执行中不再触发第二次采样，可返回受限 BUSY 或继续等待。
- 完成后重发相同的响应字节及原始采样时间，不把重发时间作为新测量时间。
- 相同键不同内容、旧 generation、旧 capture、过期结果拒绝。
- 复位后清空缓存，必须重新挑战/入网；`pdr4_bind()` 本身不能制造 boot 唯一性。

另一个更简单但体验较差的允许路线：回复不确定就明确使本次采集失败，重开完整 capture。必须以新事务统计延迟和失败，不能在同次扫描里跳编号、复用未知旧角度。

为了保持 PDR4/1 兼容，先规定如何传递 BUSY/错误以及 boot；有新增 wire 字段时明确升级版本，绝不静默改变长度/字段含义。UART 流解析还需定长/长度、CRC、帧同步、超时、DE 与实际发送完成 TC 的时序，不能只依据 TX 缓冲写入完成就翻转 DE。

回归必须覆盖请求没到、请求已执行但回复没到、重复完整回复、迟到旧回复、CRC 错、截断/粘包、同键不同内容、执行中复位、电源掉落和新事务接续。若缓存回复超出本次完整扫描预算，应明确放弃并重新收集完整新扫描，不能把扫描 start 重设到重试时刻。

## 6. O5-03：隔离已取消请求的迟到消息

现有 `StaticWindow` 与 C++ `FStaticWindow::Push()` 对不同 capture_id 直接 Fault；网络层在发新 request 时清理现有消息队列，但无法清除在途 TCP 字节。[S1,S2,S3] 原 Python 窗口实际执行：新事务收到合法旧回复后 Fault，随后合法新回复也无法恢复。没有接受旧姿势。

修改位置应在解包、会话/身份校验之后，稳定窗口 `Push` 之前，不是降低稳定算法要求。维护有界的 retired_capture_ids（取消、完成、已超时）及当前 active_id。属于同一仍有效会话且命中退休 ID 的合法回复丢弃并记数；当前 ID 正常处理。未知 ID、CRC 错、字段错、boot/profile/calibration 不一致仍明确处理为错误。

墓碑集必须有最大条目数和寿命/重连清除规则，不能变成无限缓存。不要把任何 capture_id 不同的包都随意忽略，以免隐藏其他同步问题。

验证要在 Python、C++ 与真实 UE TCP 都补：旧 ACK/旧 scan 在新 ACK 前后到达、cancel+new request 紧邻、分包/粘包、多次取消、旧扫描与新扫描同一读取批次。断言旧姿势写入为 0、一个合法新快照最多写一次，且只有确实的故障使新事务失败。

## 7. 下一轮先接哪条硬件链？

先接 A 的实际采集拓扑，不等待 C 定型。复用 PDS1/1 和已实现 UE 状态机，不再重写一套相同稳定判定到 STM32。

```text
UE 静态 request
  → 主机 HardwareBridge（PDS1 TCP 端）
  → G0（事务/扫描编号与 G0 单调时钟）
  → N1…N6 请求式真实采样
  → G0 形成一轮完整新扫描
  → HardwareBridge 校验、转换原始计数/状态
  → 现有 UE 稳定窗口和绝对限位解码
  → 预览/原子 Capture、Undo/Redo
```

G0 可以先实现一份独立、有版本的较紧凑 USB 协议，主机负责 JSON 包装；JSON 不必塞进每个 MCU。使用单一 G0 时间域或保守的 G0 派发至接收包络来界定整轮扫描，不能直接相减不同 MCU 的绝对时钟。实际节点 delay/span 可以作为补充诊断，必须标明钟域。

所有测量都应在此次请求/扫描之后取得。不得读取旧 O3 PD41 缓存然后给它新 capture_id 和时间戳。区域重启、标定变更、丢轴使整个 FullBody 结果无效，绝不填零或继承旧正常数据。

不必一开始就完成 41 轴实体：先以 G0 + 一区域 + 一个真实 AS5048 做诊断读数/标定/断线测试，再扩展一侧九轴。其余缺失轴不得伪装成真实正常数据。混合模拟只能在独立测试源和日志中明确标记，不可以 `source_kind=hardware` 的完整姿势冒充实物验收。完整生产型 UE FullBody 验收最终需要全部 41 轴真实数据，但传感器可以先固定在测试板/治具，不必已有成品全身机构。

A 与 C 共用上层 region_scan 接口，C 仅替换 N3/N4 远端四轴的数据获取。这样 C 暂缓或失败不影响已完成的软件和 A 硬件流程。

当前静态 10 Hz、500 ms、100 ms、3 s 参数作为 O4 已实现基线保留，先测出硬件表现，不擅自扩大超时掩盖故障，也不重新启用旧 60 Hz/8/14 ms 产品要求。若实际合理用途需要调整，单列变更依据和相应稳定/年龄验证。

## 8. C 四芯方案：继续条件、停止条件

同一侧近端加远端：[H2,H5]

| 指标 | A | C 优先候选 | 说明 |
|---|---:|---:|---|
| 远端板框 | 26×30 mm | 20×30 mm 顶出线 | 面积减少 23.1% |
| 远端元件数 | 47 | 66 | 新 MCU/通信/调试/保护并非免费 |
| 近远端包围盒体积之和 | 约 30817.8 mm³ | 约 29872.5 mm³ | 减少约 3.1%，不是整机净空间 |
| 计入 R4/R12 线弯占位 | 基线 | 约增加 5.1% / 8.2% | 仍是包围盒敏感性，并非真实线束扭矩 |
| 计入插拔占位 | 基线 | 约增加 12.3% | 不能只看接头针数 |

不能由总包围盒增加直接淘汰 C：在狭窄上臂中减少 6 mm 宽度、降低某一个肩部线弯阻力可能很有价值。但必须在同一个实际九轴手臂中展示这种价值。

下一轮只保留 A 参考和一套 C 优先候选，不无止境新增独立摆板方案。一起放入：相同 Manny/Quinn 480 mm 比例、相同机械轴中心和运动范围、N2/N3/N4 胸部布置、其他所有传感器线路、RF 禁布区、接口/配合头、公差壳厚和工具。先完成关键右/左结构之一的可执行 CAD，再镜像并分别核对另一侧/另一角色的比例，不能用镜像等同于全部验证。

C 进入最终路线的必要条件：

1. 解决端子/线径、电源最坏条件、失电状态和固件闭环；新板路由完成、DRC 未连接为零，警告逐项有书面处理，不能靠整类忽略。
2. 在同一全行程带线动作中，证明至少一个用户相关收益：更少干涉、更好的活动余量、较低且可重复测得的线束恢复力，或更易维护；不得牺牲其他必需动作。
3. MCU、调试、线束、连接器、组装和测试成本一起比较；不承诺更便宜。

若 A 已满足目标，而 C 仍只有板框面积优势、完整占位/手感/维修没有改善，本轮就停止扩大 C 的投入，保留为实验支线，继续 A。不是宣布 C 原理不可行。

## 9. 机械：先关节风险样件，再真实单臂

静态模式不会免除保持、精度和装配要求，也不意味着必须改成每关节手动松螺钉再锁紧。无线、桌面比例和直接摆姿方式保持不变。

顺序建议：

1. 定义输出接头、所有承力接口和真正的最大弹簧力范围，覆盖供应方曲线、制造公差、温度、磨损与后盖离散锁定增量，不能把 326 N 或假定乘 1.25 当作已知最大值。
2. 外耳反向载荷：区分前背片固定与后背片受载轴向滑移；比较前片正向可靠固定、后导向消隙/可调方案。记录扭矩—角位移、卡滞和轴向拖曳，不只缩槽宽。
3. 槽根与中断螺纹：既然不要求 1.2 kg，允许局部增厚或改变承力段，但半径 15→16 mm 的壁厚改善只是几何，不是螺纹强度通过。必须核对负载下的局部应力、牙底、工具和动作包络。
4. 摩擦材料与背片用最小试片建立面压、扭转剪切、剥离、蠕变和温度证据，确定工艺之后再放行受载单关节。
5. 受控单关节包括输出夹持、真实插头、真实电线，验证保持、操作力、反向重复性和磨损，然后组装真实肩/肘/腕全链。

沿用已约定的误差 ≤1°、重复性 ≤0.3°、保持 60 s 漂移 ≤0.5° 和代表性 1000 次往返初筛作为对应样件验收起点，记录量具不确定度；与软件稳定检测的阈值区别处理。名义约 0.65043° 外耳空程不是编码器误差，也不是已经测得的整机滑落角。[H2]

未完成这些门槛前，可以制作尺寸/装配参考件或小材料试片，但不能给全套人偶制造放行。

## 11. 不把测试规模冒充可靠性证明

继续用 1000 次已静止正常请求作为台架起始耐久批次，分别记录成功率、P50/P95/最大等待、失败原因、数据年龄、温度、供电和 boot。它不是统计意义上已经证明 99.9% 的现场可靠性。原模拟 P95 759 ms 不是实体承诺。

故障测试与健康统计分别报告，但不能把故障事件产生的旧姿势写入从统计中删除。关键不变量：旧/混合/缺失/故障测量被当成合格硬件快照的次数为零；一次合法快照最多写一次；超时有界；取消/重启后正确恢复。

所有放行分为：数字证据完成、台架样件允许、具体样件实测通过、完整设备制造允许。后一层不能由前一层自动推导。

## 12. 本轮不要求用户新增取舍

无需恢复 1.2 kg 硬门槛，不要求用户接受更大身高、更少自由度或取消无线。线径/端子选择、重试、板布局和普通机械修复由工程方案处理。只有必须改变尺寸、直接摆姿方式、无线功能或明显扩大采购成本的实际冲突，才回到用户决定。

本轮目标不是再写一套更大的计划，而是交付：**A 的真实静态采集最小闭环，C 是否继续的实物/共同总装证据，以及一套关闭对应制造风险的关节和完整单臂。**
